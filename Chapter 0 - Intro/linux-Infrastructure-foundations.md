מבחינת ההרשאות תהליך בן יורש את ההרשאת של תהליך האב שלו

במידה וזה יהיה אכן הרשאות rood הוא יקבל אוטומטית גישה מלאה לכל השרת

# תשובה 3

לינוקס מבודדת תהליכים ושולטת במשאבים של המחשב באמצעות 2 מנגנונים 
1 namespaces 
2 cgroups 
namespaces מספקים בידוד של מה כל תהליך במחשב יכול לראות ואז ניתן להגביל משאבים כליים והתהליך מבחינתו פועל לבד במחשב 
cgroups מספקת את ההגבלה של כמה מותר לתהליך לצרוך מהזיכרון ומה cpu ואוכף את מגבלות החומרה האלו 
הבסיס לקונטיינרים הוא הצורך לבודד תהליכים כך שירוצו בצורה שאינה תלויה במשאבים של המחשב הנוכחי 
ובעזרת 2 המנגנונים האלה זה אפשרי 

`unshare` זה פקודה שמאפשרת ליצור shell חדש שהוא נהיה pid 1 ולא יכול לראות תהליכים שקורים על ה host 
`nsenter` מאפשר ל host להכנס לתוך ns מסויים מתוך אותו ה ns ולהריץ פקודות 
`systemd-run --scope` נותן להריץ פקודה או סקריפט ולהכניס אותה ל cgroup מסויים מה שמאפשר להגביל את כות המשאבים שהפקודה תצרוך 


כמו כן ניתן ליצור מרחבים מבודדים עבור network שבו בעצן כל ההגדרות של ה ip tables מתנקות וגם כל הכרטיסי רשת nics שיש ל host לא יופיעו 
כדי לתת למרחב הזה לגשת לרשת נותנים לו veth pair שדרכו ניתן לגדשת החוצה

# תשובה 6

נושא העמקה זה בידוד משאבים (cgrups )
כאשר אפליקציה ב user space צריכה עוד זיכרון 
היא קוראת לפונקציה כמו malloc()
והפונקצייה הזו מתרגמת את בקשת הזיכרון ל systemcall בשם mmap
בשלב הזה המעבד עובר לקרנל והוא אחראי לבדוק לאיזה קבוצה (cgroup)
שייך ה process ומה המכסה של הזיכרון שמותרת 
ואז אם זה עומד בתנאים הקרנל מקצה דפי זיכרון ומחזיר לאפליקציה לרוץ
אם התהליך חרג מהמכסה של ה cpu שמותרת לו אז ה scheduler מקפיא את התהליך ומבצע תהליך שהוא יחסית יקר כדי להעביר את המעבד ל process אחר 
אם מדובר בחריגה מהזיכרון אז הקרנל מקפיא ותו וקורא למנגנון של OOM killer ששולח סימן הריגה ומסיים את ה process מיד 
העיקרון הזה או מה שמאפשר לקונטיינרים לעבוד בצורה צפוייה ותחת שליטה מלאה
